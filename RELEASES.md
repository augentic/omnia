## 0.39.0

Unreleased

### Added

- Per-guest outbound host grants via `Grants::hosts` in `[guest.grants]`, `[plugins.grants]`, and `runtime!` `grants: { hosts }`, with `Grants::{allows_host, covers_host}` and `omnia_core::host_pattern` for capability crates. A list holds outbound `wasi:http` requests and the redirects `HttpDefault` follows (`http-request-denied`), `omnia:model` worker `egress` (`denied`), the `registry` an `omnia:plugins` `release` load names and each request and redirect of its fetch (`denied`), and each address an `omnia:vcs` backend dials (`denied`). It matches plain host names alone, so `*` never reaches an address ([#423](https://github.com/augentic/omnia/issues/423), [#424](https://github.com/augentic/omnia/issues/424), [#425](https://github.com/augentic/omnia/issues/425)).
- Per-guest guest grants via `Grants::guests` in `[guest.grants]`, `[plugins.grants]`, and `runtime!` `grants: { guests }`, with `Grants::allows_guest`. A list holds each link call a guest makes, which fails before its target loads, and each `omnia:plugins` load, which is `denied` by the name its source registers under before anything is read or fetched ([#422](https://github.com/augentic/omnia/issues/422)).
- `omnia_wasi_vcs::Place::{locate, mounts, writable}`, which hold an `omnia:vcs` local address to the guest's mounts. A place carries the mounts its guest holds, as its grants narrow them. A backend locates each local address a `clone`, `fetch`, or `push` dials, and each directory the dial reaches beyond the place, through `locate`. It answers `Error::Denied` for one outside those mounts, or beneath no writable mount where a write needs one, and `Error::NotFound` for one that holds no directory. `MountRegistry::beneath` is the lookup it places by ([#477](https://github.com/augentic/omnia/issues/477)).
- `MESSAGING_MAX_IN_FLIGHT` and `RuntimeOptions::messaging_max_in_flight`, the most message deliveries that hold or wait for a slot of the concurrency gate at once. Unset, it is half the gate, rounded up. `RuntimeOptions::concurrent_invocations` and `RuntimeOptions::messaging_in_flight` give the gate's width and messaging's share ([#428](https://github.com/augentic/omnia/issues/428)).
- `RuntimeOptions::decommit_margin`, the freed pool slots wasmtime may hold back from reuse while it batches their resets. It is 0 at a `POOL_DECOMMIT_BATCH_SIZE` of 1 ([#430](https://github.com/augentic/omnia/issues/430)).
- `PoolExhausted` and `PoolResource`, which name the resource a full instance pool ran out of. The error of `LeaseError::PoolFull` downcasts to `PoolExhausted`, as does that of `InvokeError::Trap` when a call between guests finds the pool full. `PoolResource::variable` is the variable that sizes the resource, and the error's message names it ([#429](https://github.com/augentic/omnia/issues/429)).
- `invocations_wait_time`, a histogram of how long each message delivery, command run, call through `Runtime::dispatcher`, and `Runtime::lease` call waited for its slot of the concurrency gate, in seconds ([#429](https://github.com/augentic/omnia/issues/429)).
- A `trigger` attribute on `invocations_refused`, naming the trigger that refused each request or event: `http`, `websocket`, or the name a trigger an embedder runs itself passes to `Runtime::try_lease` ([#429](https://github.com/augentic/omnia/issues/429)).
- `omnia_test::host::Metrics`, which records the runtime's own metrics in memory for a test to read back. `Metrics::install` runs once per test process, before the first boot. `Metrics::count` reads a counter such as `processing_errors`, `Metrics::count_with` its points under one attribute, and `Metrics::observations` a histogram's count and sum ([#482](https://github.com/augentic/omnia/issues/482), [#429](https://github.com/augentic/omnia/issues/429)).
- `omnia_wasi_http::HttpHandler::serve`, which serves HTTP on a listener its caller has bound until `Runtime::stop`, then drains as the trigger's server does. It reads no `HTTP_ADDR` ([#473](https://github.com/augentic/omnia/issues/473)).
- `omnia::telemetry::{forward_traces, forward_metrics}` and `Forwarded`, which queue guest telemetry for the host's collector. Each export goes over the channel the host's exporters use, with their headers and timeout, in one attempt in the background. `Forwarded` says whether the export was queued or dropped, and why ([#467](https://github.com/augentic/omnia/issues/467)).

### Changed

- **Host views take the guest's grants:** `HostCtx::view` and `omnia_wasi_http::HttpBorrow::as_view` take `&Arc<Grants>`, so a hand-written host or HTTP backend adds the parameter, and `#[derive(HostCtx)]` leaves it unused ([#423](https://github.com/augentic/omnia/issues/423)).
- **`VcsClient` takes the guest's grants:** `omnia_wasi_vcs::VcsClient::{clone_repo, fetch, push}` take `Arc<Grants>`, so a backend adds the parameter. It refuses each address the call would dial, and each redirect it would follow, whose host `Grants::allows_host` refuses, with `Error::Denied` before anything connects. A `fetch` or `push` remote that is an address, not a name the repository records, is `Error::NotFound` ([#424](https://github.com/augentic/omnia/issues/424)).
- **`RegistrySource` takes the loading guest's grants:** `RegistrySource::acquire` and `Runtime::acquire` take `&Grants`, so a source of your own adds the parameter. A source refuses each request a fetch from the `endpoint` a load names would make, and each redirect it would follow, whose host `Grants::allows_host` refuses, with `AcquireError::Denied` before anything connects. A declared package's first use passes `Grants::all()` ([#425](https://github.com/augentic/omnia/issues/425)).
- **A named registry's fetch sends the deployment's credentials alone:** a fetch from the `registry` a load names authenticates with the deployment's `[registry."<name>".oci]` settings, never `WKG_REGISTRY_*_AUTH_BEARER` or the Docker credential store. Every host it reaches must be in the loading guest's `hosts`, so a guest that loads from `omnia.host` lists `omnia.host`, `augentic.io`, `ghcr.io`, and `pkg-containers.githubusercontent.com` ([#425](https://github.com/augentic/omnia/issues/425)).
- **Grants tables without `hosts` or `guests`:** a 0.38 `[guest.grants]` or `[plugins.grants]` table that leaves out `hosts` reaches no host, and one that leaves out `guests` reaches no guest. Their guests' outbound HTTP and worker egress, or link calls and loads, fail when made, not at boot. Add `hosts` to every table whose guests call out, as Emery's `[plugins.grants]` must. Add `guests` to every table whose guests call or load another guest, or `guests = ["*"]` to keep reaching every guest ([#423](https://github.com/augentic/omnia/issues/423), [#422](https://github.com/augentic/omnia/issues/422)).
- **Worker egress and test doubles:** an `omnia:model` worker `egress` entry ending in a numeric label (`2130706433`, `example.1`) is `invalid`, since it reads as an IP address, and `omnia_test::host::MatchedHttp` refuses a request outside the guest's `hosts` with `http-request-denied`, recording none ([#423](https://github.com/augentic/omnia/issues/423)).
- **Hand-bound handlers import `omnia:otel`:** `omnia_sdk::exports::messaging::export!` and `omnia_sdk::exports::websocket::export!` run each delivery or event inside the guest telemetry scope, so a guest that binds either imports `omnia:otel` and its deployment links `WasiOtel`. `OtelDefault` suffices.
- **Only the command run receives the command's arguments:** a guest the run calls or loads, a guest a host dispatch reaches, and a guest a trigger serves see an empty argv, whatever their grants. A `mode: server` deployment given arguments fails at startup. A guest that read the arguments outside the run takes its input in the call, or from `[env] inherit` or `omnia:config` ([#437](https://github.com/augentic/omnia/issues/437)).
- **`ModelClient::limits` has no default:** every backend states the session limits the host holds it to. A backend that took the default returns `Limits::default()`, and a client that wraps another returns the wrapped client's ([#435](https://github.com/augentic/omnia/issues/435)).
- **`ScriptedModel::limited` sets a script's limits:** `omnia_test::host::ScriptedModel::limits(self, Limits)` is renamed, so a double that wraps a `ScriptedModel` forwards its limits as `self.inner.limits()` ([#435](https://github.com/augentic/omnia/issues/435)).
- **A lease runs each root invocation:** `Runtime::lease` and `Runtime::try_lease` replace `Runtime::slot`, `Runtime::try_slot` and `Runtime::enter`, which are no longer public, and `Slot` is no longer exported ([#446](https://github.com/augentic/omnia/issues/446), [#450](https://github.com/augentic/omnia/issues/450)).
  - A lease holds a slot of the concurrency gate and a deadline `GUEST_TIMEOUT_MS` after the slot was taken. `Lease::deadline_millis` is that deadline, for the trigger to tell its guest.
  - `Lease::invoke` instantiates the guest at the server chain root and runs a call on it before the deadline. A call that outlives it is dropped with its store. It fails with `LeaseError::Enter`, `LeaseError::PoolFull` or `LeaseError::Timeout`. `LeaseError` is `#[non_exhaustive]`, so a match on it takes a wildcard arm ([#482](https://github.com/augentic/omnia/issues/482)).
  - A trigger an embedder runs itself replaces `slot` and `enter(guest, chain)` with `runtime.lease(guest).await.invoke(async |mut entered, instance, _bound| ..)`. `Entered` implements `AsContextMut`, so `&mut entered` passes wherever `&mut store` did, and `store.run_concurrent(..)` becomes `entered.as_context_mut().run_concurrent(..)`.
  - A trigger that refuses at a full gate replaces `try_slot` with `runtime.try_lease(guest, trigger)`, whose `trigger` names it on `invocations_refused` ([#429](https://github.com/augentic/omnia/issues/429)).
  - Dropping `Entered` drops the store, then frees the slot, so the trigger counts against `MAX_CONCURRENT_INVOCATIONS`. A call whose remaining work runs to a limit of its own re-arms the deadline with `Bound::reset`.
- **`Handler::max_in_flight` is required:** an `omnia_wasi_messaging::Handler` states the most messages it takes at once, and `dispatch` reads no further from its stream while that many are with the handler. A hand-written handler returns its bound. A backend whose `Endpoint::consume` runs its own delivery loop keeps no more than `max_in_flight` messages with the handler ([#428](https://github.com/augentic/omnia/issues/428)).
- **`Handler::stopped` is required:** an `omnia_wasi_messaging::Handler` says when it takes no more messages, and `dispatch` reads nothing more from its stream once it does. `MessagingHandler`'s resolves once the runtime stops. A hand-written handler returns a future that resolves at its own stop, or one that never resolves. A backend whose `Endpoint::consume` runs its own delivery loop hands the handler nothing more once `stopped` resolves, waits for the messages it has handed over, and returns `Ok`. A consumer that returns before the stop still fails the messaging server ([#473](https://github.com/augentic/omnia/issues/473)).
- **Messaging takes half the gate by default:** message deliveries hold or wait for at most half the slots of the concurrency gate, rounded up, so a deployment that serves only messaging runs half as many at once. Set `MESSAGING_MAX_IN_FLIGHT` to the gate's width to run as many as 0.38 did. Messages past the share wait in the transport. NATS core drops them once async-nats's buffer fills, and the in-memory broker once it falls 32 behind ([#428](https://github.com/augentic/omnia/issues/428)).
- **Messaging loads its guest before it takes a slot:** a delivery whose declared guest loads at its first use waits for its slot of the concurrency gate only once the load is done, as an HTTP request and a WebSocket event do, so a slow load holds no slot. The delivery's place in `MESSAGING_MAX_IN_FLIGHT` covers the load ([#450](https://github.com/augentic/omnia/issues/450)).
- **Every importer of a linked function agrees:** guests that import one linked function with different signatures, a parameter's name included, no longer stand together. A deployment that loads two such guests at boot fails, and a later one is refused. 0.38 compared importers' asyncness alone. Build every importer of a function from the same WIT ([#431](https://github.com/augentic/omnia/issues/431)).
- **Public API nothing used is withdrawn:** `Deployment::assemble` is the one way to build a runtime, and only the runtime builds a store context ([#448](https://github.com/augentic/omnia/issues/448)).
  - Removed: `Runtime::registry_config` and `RuntimeParts::registry_config`, `Runtime::http_trigger_router`, `Deployment::selector`, `GuestSelector`, `FirstArgSelector`, `CliRoutes`, `Routes::cli`, and the `ModelClient` and `VcsClient` impls for a boxed client. `Routes::new` takes the HTTP, messaging and WebSocket tables, and `InProcessLinks::new` takes nothing.
  - Crate-private: `StoreConfig`, `StoreBase::new`, `StoreBase`'s fields, `Guest::local` and `Deployment::into_registry`.
  - Hidden from the docs, for omnia's own crates: `RuntimeParts`, `Runtime::from_parts`, `RegistryParts`, `Registry::assemble`, `LinkSeam`, `NoLinks` and `Plugins::install`.
  - No longer re-exported from `omnia`: `RuntimeParts`, `RegistryParts`, `StoreConfig`, `StoreFactory`, `LinkSeam`, `NoLinks`, `CliRoutes`, `InProcessLinks`, `GuestSelector`, `FirstArgSelector`, `Cli`, `Command` and `Parser`.
  - `omnia_cli::plan` returns a `Plan`, either `Plan::Run` or `Plan::Compile`.
- **Two unmarked command guests fail:** when two or more boot guests export `wasi:cli/run` and none is marked `command = true`, command mode fails naming them and advising the mark. It failed with "trigger `cli` has 2 capable guests … but no routes", which sent the operator to routes the cli trigger cannot take ([#448](https://github.com/augentic/omnia/issues/448)).
- **The generated `main` runs `compile`:** `<runtime> compile <wasm> [-o <path>] [-t <triple>]` compiles under the compile-affecting settings its environment sets, so a `run` under the same environment loads the artifact. A runtime built without omnia's `jit` feature refuses it, naming the feature. It was refused as "the generated `main` only supports `run`" ([#448](https://github.com/augentic/omnia/issues/448)).
- **A call through `Runtime::dispatcher()` takes a slot:** each call is a root invocation, so it waits at a full concurrency gate and counts against `MAX_CONCURRENT_INVOCATIONS`, freeing its slot once the callee's store drops. A store's own dispatcher takes none. A host-side caller that holds a slot while it dispatches waits on itself at a full gate, so it drops the slot first ([#448](https://github.com/augentic/omnia/issues/448)).
- **Link calls run through `Dispatcher::invoke`:** a guest's link import calls its target through the calling store's `Dispatcher`, the one a host binding calls a guest through, so the two take one path ([#449](https://github.com/augentic/omnia/issues/449)).
  - Removed: `Dispatcher::ensure`, `Runtime::serve_links`, and the `serve`, `publish`, `discard`, `remove` and `shutdown` methods of `LinkSeam`.
  - Crate-private: `StoreFactory`, `FreshCall` and `call_fresh`.
  - `Dispatcher::invoke` matches an interface's name exactly, so a call to `example:link/echo@0.1.0` no longer reaches a guest that exports `example:link/echo@0.1.1`, and a link import reaches only an export of its own name. Build an importer and its exporter from the same WIT.
  - A call over `MAX_DISPATCH_DEPTH` fails before its target loads. A host binding's call loaded a declared target first.
  - A call to a guest that does not export the interface it names fails with "guest `<id>` exports no interface `<interface>`". A link call failed with "guest `<id>` is registered but exports no linked interface".
  - A link call that outlives `GUEST_TIMEOUT_MS` fails with "dispatching `<interface>/<func>` to guest `<id>`: timed out after <bound>", and a store-bound handle in a host binding's arguments with "a <kind> handle cannot cross the link seam (call to `<interface>/<func>`, target `<id>`)".
  - `Runtime::shutdown` is the same as `Runtime::stop`, so a link call made after it runs. In 0.38 it failed.
- **`EPOCH_TICK_MS=0` fails startup:** a deployment that sets it stops, as one that sets `GUEST_TIMEOUT_MS=0` does. 0.38 raised it to 1 ms ([#451](https://github.com/augentic/omnia/issues/451)).
- **Pool slots are reset one at a time by default:** `POOL_DECOMMIT_BATCH_SIZE` defaults to 1, wasmtime's own default, so each freed slot is reset as its instance is dropped. A batch saves syscalls only on Linux 6.14 or later, where seccomp allows `process_madvise`. Set `POOL_DECOMMIT_BATCH_SIZE=16` to batch as 0.38 did ([#430](https://github.com/augentic/omnia/issues/430)).
- **The unset pool totals cover a batched decommit:** above a `POOL_DECOMMIT_BATCH_SIZE` of 1, the unset `POOL_TOTAL_MEMORIES` and `POOL_TOTAL_TABLES` add `RuntimeOptions::decommit_margin`, and so does `POOL_TOTAL_STACKS` while `ASYNC_STACK_ZEROING` is on. A set total is used as is, so a deployment that sets one and raises the batch adds the margin itself ([#430](https://github.com/augentic/omnia/issues/430)).
- **HTTP and WebSocket count in their handlers:** `HttpHandler::handle` and `WebSocketHandler::handle` count and log what they handle, so an in-process caller such as `omnia_test::host::send` counts on `processing_errors`, and on `event_counter` for an event, as the server loops did. The server loops count nothing of their own ([#482](https://github.com/augentic/omnia/issues/482)).
- **A WebSocket event stream that ends fails the server:** `WasiWebSocket`'s server returns an error when its backend's `Endpoint::events` stream ends before `Runtime::stop`, as messaging's does when its consumer ends, so the process exits for its orchestrator to restart it. It returned `Ok`, so a deployment that served other triggers ran on without WebSocket, and one that served WebSocket alone exited 0 ([#473](https://github.com/augentic/omnia/issues/473)).
- **`OtelDefault` exports guest telemetry:** it forwards each guest's spans and metrics to the collector the host's own telemetry goes to, with the headers and timeout the `OTEL_EXPORTER_OTLP_*` variables set. A deployment exports guest telemetry once `OTEL_EXPORTER_OTLP_ENDPOINT` is set, with no backend swap, and a slow or absent collector never holds a guest. A full queue answers `unavailable`, and an export over 4 MiB `invalid`. With no endpoint it drops guest telemetry as it did, and it no longer warns at connect. A deployment that wired `omnia_opentelemetry::Client` for guest export can wire `OtelDefault` instead ([#467](https://github.com/augentic/omnia/issues/467)).
- **Host and guest telemetry share one transport:** the host's exporters and the guest queues share one lazily connected gRPC channel per collector, on a runtime thread of their own, so `Telemetry::build` needs no tokio runtime and export no longer depends on the caller's. `telemetry::flush` also waits, for at most each signal's timeout, for the guest telemetry queued before it. `telemetry::resource` and the guests' route publish whether or not omnia's subscriber installs. An `https://` endpoint, or a schemeless one without `OTEL_EXPORTER_OTLP_INSECURE=true`, still fails startup, and the error now names the variable that set it ([#467](https://github.com/augentic/omnia/issues/467)).
- **A `--mount` spec that names a key twice fails:** each of `path`, `name`, and `writable` appears at most once, and a bare token counts as `path`. It used to keep the last value ([#515](https://github.com/augentic/omnia/issues/515)).
- **A mount at or beneath a writable mount fails startup:** whatever its own permission, so only read-only mounts nest. Directories are told apart by identity, so a second mount of a writable mount's own directory fails too. A 0.38 deployment that nests a mount in a writable one moves the inner directory out, or mounts the outer one read-only ([#520](https://github.com/augentic/omnia/issues/520)).
- **Mount paths are canonical:** `MountRegistry` records each mount's canonical path, so `Place::path` and `Workspace::local_path` pass through no symlink, and `omnia_test::host::Scratch::path` is canonical to match. A mount whose path is removed or replaced while guests run keeps serving the directory opened at startup. Each store reopened it by path, and left it out, with a warning, once the path was gone ([#520](https://github.com/augentic/omnia/issues/520)).

### Fixed

- Record a `tracing` event's `monotonic_counter.`, `counter.`, `histogram.`, or `gauge.` metric whatever `RUST_LOG` is, in a guest and on the host. Below the run's level such an event was dropped, so a guest's `info!` counter never reached a server running at its default `warn`. `RUST_LOG` still governs the console and spans, and under `tracing-log` a `log` record still dispatches only at the run's level ([#426](https://github.com/augentic/omnia/issues/426)).
- Compile `#[omnia_sdk::otel::instrument]` on an `async fn`, `otel::scope`, `otel::flush`, `command::execute`, `http::serve`, and `messaging::handle` on a native target. Each was `wasm32`-only, so a guest crate that instrumented a handler did not build natively. On a native target `scope` installs no telemetry, so an instrumented handler's span reaches the test's own subscriber.
- Stop an HTTP guest whose request is dropped before its response head. The guest ran on with no wall-clock bound, holding its slot of the concurrency gate until it answered, or for good if it never did. An HTTP guest's `GUEST_TIMEOUT_MS` now counts from when it takes its slot, so it bounds instantiation too ([#463](https://github.com/augentic/omnia/issues/463)).
- Stamp an HTTP request's `x-deadline` when it takes its slot of the concurrency gate, the instant its `GUEST_TIMEOUT_MS` counts from. It was stamped before the request was routed, so a declared guest's first request was told a deadline its own load had already spent from ([#427](https://github.com/augentic/omnia/issues/427)).
- Count a message delivery's and a WebSocket event's `GUEST_TIMEOUT_MS` from when it takes its slot of the concurrency gate, so the timeout bounds instantiation as well as the call, and the `deadline` its guest reads is the one the host enforces. Each trigger timed the call alone, from after instantiation, so instantiation ran unbounded, and a guest ran past the deadline it was told by as long as it took to instantiate ([#450](https://github.com/augentic/omnia/issues/450)).
- Keep HTTP and WebSocket served under a backlog of message deliveries. Deliveries waiting for a slot of the concurrency gate take every freed slot first, and `dispatch` handed the host every message it read, so a burst refused requests and events until it drained, and sustained load refused them for good. Messaging now holds or waits for no more than its share of the gate ([#428](https://github.com/augentic/omnia/issues/428)).
- Load a declared guest once when its first uses arrive together. Each acquired and compiled the guest itself, and HTTP and WebSocket resolve a guest before they take a slot of the concurrency gate, so a burst of cold requests ran a fetch and a compile per request that the gate bounded none of. The first uses now share one load and its outcome, error included, and dropping one fails none of the others. A panic in the load reaches each of them as `GuestError::Internal` ([#432](https://github.com/augentic/omnia/issues/432)).
- Settle racing admissions of one guest identity as the one that seated first. With omnia's `link` feature, a `Runtime::register`, `Runtime::admit_bytes`, or `Runtime::admit` that raced another of the same identity could fail as `GuestError::Internal`, and an `omnia:plugins` load of a path or package as `LoadError::Other`. A racing registration now attests the same bytes and grants or reports `GuestError::Conflict`, and a racing load attests the same bytes or answers a `conflict` ([#432](https://github.com/augentic/omnia/issues/432)).
- Refuse a guest that disagrees with a registered guest on a linked function's signature, whichever of the two seats first. Only each function's first boot importer was checked against its exporter, so a late importer, a second importer, and every pair under a manifest of path guests went unchecked until a call crossed the skew. Such a call could trap after the exporter had run, or read a result the exporter never returned as `false`. A refused seat is `GuestError::Invalid`, not `GuestError::Internal`, and an `omnia:plugins` load answers `invalid`, not `other` ([#431](https://github.com/augentic/omnia/issues/431)).
- Release a runtime's engine and pooling reservation when its last handle drops, whether or not `Runtime::shutdown` ran. A runtime whose guests export a linked interface held handles to itself in its link routes, so it kept both until `shutdown` cleared them ([#449](https://github.com/augentic/omnia/issues/449)).
- Stop a saturated HTTP trigger on Linux failing requests with `500`. At 0.38's `POOL_DECOMMIT_BATCH_SIZE` of 16, a freed memory waited to be reset after its invocation's slot of the concurrency gate was freed, so a request the gate admitted could find the pool full though no guest called another. The batch now defaults to 1, and the decommit margin covers a raised one ([#430](https://github.com/augentic/omnia/issues/430)).
- Answer `503` with `Retry-After: 1`, not `500`, to an HTTP request the concurrency gate admits but the instance pool has no room for, and log it at `warn`. `Lease::invoke` fails with `LeaseError::PoolFull`, and `invocations_refused` still counts gate refusals alone ([#430](https://github.com/augentic/omnia/issues/430)).
- Count an HTTP request or WebSocket event refused at a full concurrency gate on `invocations_refused` alone, and log it at `debug`. HTTP also counted each such `503` on `processing_errors` and logged it at `error`, and WebSocket did the same for each refused event, so a saturated gate read as failing guests ([#482](https://github.com/augentic/omnia/issues/482)).
- Drain messaging and WebSocket on the first shutdown signal, as HTTP does. Each went on taking messages or events after the signal and never returned, so the process ran until a second signal or the orchestrator's kill, and either one cut off the work in flight. Each now takes no more work, waits for what it holds, and returns. Every trigger also checks for the stop before it takes more work, so none takes a connection, message, or event that arrives with the stop ([#473](https://github.com/augentic/omnia/issues/473)).

### Security

- Confine `SqlDefault` to the database it opened. Through `ATTACH`, `VACUUM INTO`, or `PRAGMA temp_store_directory`, a guest could read, write, or create a SQLite file anywhere the host user can. Each now fails with `denied`. So do a plain `VACUUM`, which SQLite runs through an attached database, and `PRAGMA data_store_directory`. The connection also runs in SQLite's defensive mode, so ordinary SQL cannot corrupt the schema. Every `omnia-wasi-sql` release up to 0.38.1 is affected ([#519](https://github.com/augentic/omnia/issues/519)).
- Serve each store's `wasi:filesystem` preopens from the directories `MountRegistry::open` opened at startup. Each store reopened every mount by its path. A guest that could write an outer mount could replace an inner mount's directory, or a symlink its path ran through, with a relative link. The next store then preopened the link's target, anywhere on the host, with the inner mount's permissions. A mount's path is now canonical, and a mount at or beneath a writable mount fails startup. Every `omnia-core` release up to 0.38.1 is affected ([#520](https://github.com/augentic/omnia/issues/520)).
